# 阶段性汇报 PPT 制作说明 (交付 Codex)
=========================================

> **用途**: 本文档是给 Codex（或任何 PPT 生成工具）的完整制作规格。
> **目标**: 12 页汇报 PPT, 讲清楚"GRPO 强化学习在 Llamole SFT 模型上的物理反馈优化"这一工作。
> **配套**: 数据全部在 `experiments/` 下, 每个数字都可追溯。

## 0. 核心叙事 (先读这一段)

```
问题 → 方法 → 证据 → 归因 → 风险 → 计划
```

**不要**按"我做了什么"的时间线讲, 要按"**证据链的强度**"讲。
听众（领导/审稿人）最关心一件事: **这个提升是真的吗? 会不会是骗分 (reward hacking)?**

所以第 5-7 页是全篇重心（占 6 分钟），其余是铺垫和收尾。

### 第 2 页 —— 问题与动机

**标题**: SFT 模型能生成类药分子, 但它只是"静态模仿", 无法响应真实物理约束

**配图**: B5 (SFT vs RL 概念对比图)

**要点**:
- 已有 SFT 模型: 6 个 GBM 靶点、583 个 PubChem 活性分子、QA 格式训练
- 它的局限不是"不会生成", 而是"不知道生成的分子好不好"
- 强化学习的价值: 把**物理打分器变成可探索的信号**

**演讲锚点**: "**我们要给 SFT 模型装上一个物理反馈的搜索引擎。**"

---

### 第 3 页 —— 方法: 三层架构与双 LoRA 设计

**标题**: RL 以独立 LoRA 叠加在 SFT 模型之上, 完整保留原有化学知识

**配图**: B1 (三层 adapter 架构图) ★ 这页的图是全场最重要的一张

**要点**:
- **关键设计**: SFT LoRA 冻结, 同时充当 **prior (KL 锚点)** 和 **CLIP 参照**
  - KL 定义因此是干净的: `KL(agent ‖ prior)`, prior 确实代表"训练好的化学模型"
  - RL LoRA 只改**策略**不改**知识**, 所以 30 步见效且无灾难性遗忘
- 一句话: "SFT 模型是我们原来的模型, RL 是它之上的第三个 adapter"

**可加**: A3 (M3 训练曲线) 放右下角, 佐证 "30 步就收敛"

**⚠️ 必答问题**: 为什么用三 adapter 而不是直接微调 SFT LoRA? (审稿人一定会问)

---

### 第 4 页 —— 奖励函数设计

**标题**: 加权几何平均的 MPO 奖励, 硬约束 + 软惩罚双层结构

**配图**: 公式居中 + 右侧小表

```
Reward = ∏ᵢ sᵢ^wᵢ        (加权几何平均, REINVENT4 风格)

s = [Vina, DILI, hERG, BBB, TPSA, MW, PGP, AMES, QED]

硬约束违反 → prune (不进入 advantage)
端点越界   → floor 惩罚 (不用 0 硬归零)
```

**右侧小表** (三种聚合方式的实测对比):

| 聚合方式 | ρ(reward, pIC50) | 稳定性 (DILI ±0.1 最坏相对影响) |
|---|---|---|
| **geometric** | +0.281 | **14.0%** ← 采用 |
| arithmetic | +0.101 | 4.6% |
| harmonic | +0.320 | 70.3% ← 判别力高但极不稳定 |

**要点**:
- 为什么不用算术平均: 端点归零会把整个 reward 拉成 0, 毒化统计
- 为什么不用调和平均: 判别力只高一点, 但单端点 0.1 抖动引起 **70%** reward 变化 → **LLM 收到的是噪声而非梯度**
- 硬截断阈值是**实测得出**的, 不是拍的

**演讲锚点**: "对 LLM 反馈循环来说, **信号抖动比判别力更重要**。"

### 第 5 页 —— 主结果 (★ 核心之一)

**标题**: GRPO 使 reward 中位数提升 52%, 8 个性质维度全面改善

**配图**: **A1** (`main_result.png`) —— 主视觉

**要点**:
- 评估设置: 固定 8 prompt × 50 分子/prompt, seed=1234, Vina + admet-ai (CPU)
- **reward 中位数 +52.1%** (0.2731 → 0.4153), 均值 +31.1%, Vina -7.467 → -7.824 kcal/mol
- 显著性: Mann-Whitney p=0.0021 (单侧); 逐 prompt 胜率 7/8; 跨 prompt 配对 t p=0.0037

**配图补充**: 右下角放逐 prompt Δ 明细小表 (8 行, 数据见 §1)

**演讲锚点**: "中位数提升 52% 比均值提升 31% 更值得强调。均值会被左尾拉低, **中位数代表'典型分子'的真实改善**。"

### 第 6 页 —— 机制证据: 违规率下降 (★ 核心之二)

**标题**: 违规率与截断率同时下降, 排除 reward hacking

**配图**: **B2** (违规率对比图)

**要点**:
- **这是最有力的反 hacking 论据**。如果 RL 在骗分, 最常见路径是:
  ① 生成结构守卫拦不住的畸形分子 ② 触碰硬约束边界
  - 实测两者**都降了** (-15.4% / -22.5%)
- **8 维度的方向性反证**:
  - BBB +12.3% (↑ 好) —— 而 SFT 数据本身**偏向低 BBB** (偏置检查 t=-9.07)
  - hERG -17.1% (↓ 好), PGP -25.5% (↓ 好), AMES -11.2% (↓ 好)
  - **RL 的改善方向与数据偏置相反** → 说明它学的是 reward 指定的物理, 不是数据捷径

**演讲锚点**: "各位可能会问: 你们的 reward 涨了, 会不会是模型在骗分? 我们查了两种最常见的作弊路径——结果**违规率反而降了 15% 和 22%**。更关键的是, SFT 数据本身就偏向低 BBB 分子, 而 RL 把 BBB 提升了 12%——**方向和数据偏置是相反的**。"

---

### 第 7 页 —— 消融实验 (★ 核心之三)

**标题**: 4 组消融定位 β_kl=0.08 为最优, 多样性过滤对分布外推有实际贡献

**配图**: **A2** (`m4_ablation.png`) —— 主视觉

**配图补充**: 下方放 4 行汇总表 (数据见 §1)

**要点**:
- **β_kl 是最敏感的超参**, 存在明确最优值:
  - β_kl=0.02 → 输出长度崩塌 (~60-90 tokens vs ~200), KL 飙升到 0.345 → **策略塌缩**
  - β_kl=0.08 → 平衡 (最优)
  - β_kl=0.15 → 过度约束, reward 出现**负斜率**
- **M4-C 说明多样性过滤确实有贡献, 但机制比"防 prompt starvation"温和**:
  - 去掉过滤后中位数从 +52.1% 降到 +44.7%, Mann-Whitney p 从 0.0021 弱化到 0.2595
  - 即: 过滤的主要价值是**让提升更稳定、更显著**, 不是避免某几个 prompt 霸占配额
  - ⚠️ **不要说成"去掉过滤就崩了"** —— 实际是"变弱但没崩"

**演讲锚点**: "M4-C 量化了多样性过滤的边际价值: 中位数从 52% 降到 45%, p 从 0.002 弱化到 0.26。提升还在, 但**变得不那么显著**。所以过滤的价值是让提升更稳。我们一开始的假设是后者, 数据纠正了我们。"

### 第 8 页 —— 数据质量与偏置审查

**标题**: 主动披露 SFT 数据的统计偏置, 证明 RL 提升不是数据捷径

**配图**: **B3** (偏置检查结果图) + 右侧/下方放数据表

**要点**:
- 方法: 对**共享 Murcko 骨架**的分子对 (只改 R-group) 做 Δ 统计, 检验均值是否偏离 0
- **关键技术细节 (值得强调)**: 配对方向必须**外生** (用 SMILES 字典序), 否则:
  - 按数据原始顺序 → t=-12.3, 造出**假偏置**
  - 对称化取 (+d/-d) → t=0, **检验失效**
  - ✅ SMILES 字典序 → t=+2.69, 检验有效
- 结论: 数据确实有偏置 (TPSA/BBB), **但 RL 在 BBB 维度的改善方向与偏置相反** → RL 确实在对抗偏置

**演讲锚点**: "我们主动查了 SFT 数据有没有系统性偏置, 结论是**有**。但正因为我们查了并且公开了, 我们才能用'RL 的改善方向与数据偏置相反'来证明提升是真的。"

### 第 9 页 —— 方法改进: 成对差分 Advantage

**标题**: 引入 PBCNet2.0 的成对差分思想, 缓解 reward 左尾稀释问题

**配图**: **B4** (两种归一化方式示意) + 四模式对比表 (数据见 §1)

**要点**:
- 依据: PBCNet2.0 的 readout 只做 `emb1 - emb2`; 论文指出拼接会让模型退化为"记忆配体结构"
- 映射: 我们的 reward 里混着大量**与组内对比无关**的常数偏移 (TPSA 归一化、MW 分段、ADMET 地板), 会稀释真实相对差异
- **发现并修正了纯 pairwise 的缺陷**: 纯 pairwise 把所有组拉到同一尺度 (跨度恒为 1.0), 抹平了"信息量差异" → 我们提了 `pairwise_scaled` 折中
- **兼容性保证**: 默认仍是 zscore, 行为**逐位不变**, 历史实验完全可复现 (28/28 单元测试通过)

**⚠️ 若时间紧**: 这页只讲"我们借鉴了一个新方法并做了改进"即可, 不展开细节
